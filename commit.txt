Two real bugs, both caught by reading my own first-run output rather
than trusting the code:

1. naive_orbit computed as 1 for every n, not 2^n. The naive action's
   B4 value stays fixed at B forever (bnot(B)=B), so tracking the value
   alone collapses every displacement to the same state. The Lean
   file's naive construction gets its real 2^n orbit from a SEPARATE
   phase bit carried alongside the value (MLQubit{val, phase}), which
   the first version of this file never modeled. Fixed by tracking
   (value, phase) pairs for the naive action; now matches 2^n exactly
   for n=1..6, computed by direct enumeration over all 4^n
   displacements, not asserted from the Lean theorem's name.

2. Mistranscribed the actual claim in SIC_Multilattice_Proof.lean §11.
   First version checked "is d^2/(d+1) an integer" and got false for
   every n, which happened to look consistent with the file's prose but
   wasn't actually testing what the file says. The file's real claim is
   that d^2/(d+1) is never a PERFECT SQUARE in Q for d=2^n, n>1. Since
   gcd(d, d+1)=1 always, d^2/(d+1) is already in lowest terms, so it's
   a perfect square in Q exactly when d+1 is a perfect square in Z --
   fixed the check to test that directly. Running it found a real
   counterexample: n=3, d=8, d+1=9=3^2, so d^2/(d+1)=64/9=(8/3)^2 IS a
   perfect square. That specific claim sits in a comment block in the
   Lean file, not inside a proved theorem -- never machine-checked by
   the Lean kernel at all, and false as stated once actually computed.

What the corrected report shows, all computed, none cited a second
time: at n=1 (d=2), the Belnap evidence-counting Born rule and the real
QM Hadamard's |amplitude|^2 agree exactly, 1/2 both ways, one in plain
integers with no square root anywhere, the other via a genuine complex
1/sqrt(2) amplitude (reused fibonacci_qc::Complex rather than a second
complex type) -- FDE reproduces QM exactly here, not approximately.
For n>1, the naive product-lattice orbit is proved and now measured
short of 4^n at every n checked. The corrected multilattice's orbit
does hit 4^n exactly, computed the same way. And the further, informal
claim about d^2/(d+1) never being a perfect square past n=1 does not
hold in general, which the report now states plainly rather than
repeating the file's own comment as settled.
