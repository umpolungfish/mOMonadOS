Vox: walk the program instead of sweeping it

The Rust lane lifted linearly: decode a section start to end and call the whole
thing a function. That reads padding and embedded data as code and can only
guess where one function ends, so its verdicts answered a different question
from the Python lane's.

vox_decode::descend walks instead. From the entry point and every direct call
target, one instruction at a time, following the edges the program has. A call's
target is a new function and the call returns; a conditional takes both edges;
an unconditional jump takes one. What descent cannot follow is an indirect
transfer, which is what ⊙ is for, so the remainder is swept afterwards rather
than dropped.

vox::elf_function_symbols seeds it. A shared object's own entry calls almost
none of its exported functions, so descent from the entry alone misses them.
Reading STT_FUNC out of SHT_SYMTAB and SHT_DYNSYM is what turns a handful of
reachable functions into the program.

Trailing padding is trimmed before the word is built. Left on, every function
ends in a run of ⊣ and the verdict moves for a reason that belongs to the
alignment rather than to the code.

instruction_of is now the single place a decoded instruction becomes an
Instruction. Descent and the sweep were synthesising the operand string
differently, so the same byte read as ◻ in one path and ⊞ in the other.

On /bin/ls: 189 functions before symbol seeding, 295 after, and 1680 once the
sweep stops stitching unrelated remainders together.

Not converged, and worth naming rather than leaving to be discovered. The Python
lane reports 584 functions for the same binary against this lane's 1680. Both
now use descent, symbol seeding and the same boundary rule, so the difference is
in the sweep: that lane decodes the leftover from a linear disassembly, which
self-synchronises, while this one decodes byte by byte and advances by one on a
failure, which can leave misaligned fragments. That is the next thing to fix,
and it is a difference in how the remainder is read, not in what the Grammar
says about it.
