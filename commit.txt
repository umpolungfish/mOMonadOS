Erdős 41 on the metal, and the catalog the kernel was reading was stale

Booting to check what the kernel already carried for these problems, I found it
loading 8057 catalog entries against a canonical 8202. The kernel does not read
the file; it embeds catalog_ask_subset.rs, generated from the catalog, and the
generated copy was 145 entries behind. Regenerated: 8199 at boot. The generator
is the fix, not the file — the copy was never meant to be touched.

Added the Erdős 41 walk. The Lean side now proves C(k,3) ≤ 3N from distinct
triple sums; this computes it, which is the rule the other walks keep — a step
that printed a number it had not derived would be a slideshow.

The witness has to be built, and greedy does not build it. Taking the next
integer that keeps the triple sums distinct stalls at four elements for every N,
because from {1,2,3,4} everything collides at 1+2+5 = 1+3+4. That witness would
have satisfied the bound at every N and looked like agreement, which is worse
than no witness. The walk descends exhaustively for the largest such subset
instead: k = 5, 6, 6, 7, 7 for N = 10, 15, 20, 25, 30.

Worth reading off the numbers: counting allows k ≤ (18N)^(1/3), which is 8.1 at
N = 30, and the true maximum is 7. The bound is nearly tight where it can be
checked. That is the whole difficulty of the problem — Erdős asks whether the
ratio VANISHES, and counting cannot see the difference between a constant and a
vanishing one.
