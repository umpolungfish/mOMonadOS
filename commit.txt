The Triple Frame module says where its numbers come from.

check_frobenius reported a rho that was either copied from the Python
implementation or invented by a length heuristic, in the same field, with
nothing distinguishing them. Reported as "12/12 Frobenius-closed, same rho
values as Python", which is a table lookup returning Python's own numbers: it
cannot disagree, so it is not a check on anything.

FrobeniusResult now carries rho_provenance, and the reports print it. A
tabulated value says so and says it was not independently computed. The
heuristic says it is not a spectral radius.

Because it is not one. compute_rho was documented as "approximate spectral
radius from adjacency structure" and computes sqrt(n) scaled by the
split-to-fuse fraction, with no adjacency matrix and no eigenvalue anywhere in
it. Renamed estimate_rho_by_length and documented for what it does, since under
the old name a custom word returned an invented number wearing the name of the
quantity the table holds.

sqrt_f32 was a hand-rolled Newton loop on the premise that no_std has no sqrt.
The crate already depends on libm and fibonacci_qc.rs uses it throughout.
