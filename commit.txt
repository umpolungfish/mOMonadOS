Truncate strings by character, not by byte

`triple` died on "byte index 45 is not a char boundary; it is inside '→'". The type
expansion table clipped each domain reading with `&s[..s.len().min(45)]`, and byte 45 of
that row lands in the middle of an arrow.

This is the third crash of this shape — hqe, hop and pericyclic_frobenoid all byte-sliced
Shavian tuples — so the fix is a place to put it rather than another local repair.
`text::clip` takes characters and cannot split one. `text::clip_ellipsis` marks what it
dropped, so a truncated reading is not read as a complete one.

Counting characters is also what the surrounding format wanted. `{:>8}` counts characters,
so the byte-length clip in the IUFT distance matrix header mis-aligned every column whose
gate name was not pure ASCII. That site is on the same helper now.
