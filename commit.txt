The SIXTEEN_3 trilattice's register gates now run batched on GPU, checked
bit-for-bit against the CPU implementation they're a port of, not assumed
correct because they compiled.

Reg16_3 (imasm_core::imasm16_3) is a plain 4-bool tuple over the lanes
[T, F, t, f], and every op on it -- union, meet_t, join_t, meet_c, join_c,
leq_i, leq_t, leq_c, truth_swap, info_swap, invol -- is a fixed,
data-independent per-lane bitwise op or permutation, never a branch on the
value's content. That's a fixed-width elementwise/permute kernel, so it
batches onto GPU as one kernel launch over N registers instead of N
sequential scalar calls. New module `src/gpu_sixteen3.rs` (hosted-only,
gated the same way live_hud already gates its own std::thread use) carries
three CUDA kernels, compiled at runtime via NVRTC (cudarc, dynamic loading,
no build-time link requirement): one for the five binary gates, one for the
three lane-swaps, one for the three order checks, each register packed as
a single byte.

`gpu16_3 verify [n]` runs all eleven gates on n random register pairs once
on the GPU and once on the CPU scalar functions and reports where, if
anywhere, they disagree. Ran it at n=1,000,000 (11 million checks, RTX
4070, under a second) and n=20,000,000 (220 million checks, ~2 seconds):
zero mismatches both times. Bare-metal build (no `hosted` feature) still
compiles clean -- cudarc is an optional dependency gated into `hosted`
only, so no_std never sees it. Full test suite: 259 passed, 0 failed.

This grew out of checking whether the trilattice's own catalog entry
(`sixteen_3_trilattice`) sits close to `real_swendsen_kernel` /
`ising_navigator`, the two entries in this catalog that already name a
real CUDA kernel as their implementation. The tuples share only 3 of 12
axes, genuinely different objects, but the one shared axis that bears on
whether something belongs on a GPU -- Stoichiometry, both reading "many
identical" -- matched. Minted as its own ob3ect first (`sixteen3_gpu_tensor_kernel`,
grounded, tri-ancestral T, tier O2dag) before writing the kernel, in the
ob3ect repo, not this one.
